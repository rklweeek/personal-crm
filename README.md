# Личная CRM

Контакты людей, которых я знаю лично. Подробнее об идее — `specs/01-продуктовая-идея.md`.

## Как запустить

### База данных (PostgreSQL в Docker)

Нужен установленный и запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/).

1. Если файла `.env` ещё нет — скопируйте `.env.example` в `.env` и заполните значения:

   ```
   POSTGRES_USER=crm
   POSTGRES_PASSWORD=придумайте-длинный-пароль
   POSTGRES_DB=personal_crm
   POSTGRES_PORT=5432
   DATABASE_URL=postgresql://crm:тот-же-пароль@localhost:5432/personal_crm
   ```

   `.env` хранит пароль, поэтому в git он не попадает.

2. Запустите базу (в папке проекта):

   ```
   docker compose up -d
   ```

3. Проверьте, что база работает:

   ```
   docker compose ps
   ```

   В колонке STATUS должно быть `Up ... (healthy)`.

4. Зайти в базу из терминала:

   ```
   docker compose exec postgres psql -U crm -d personal_crm
   ```

   Выход — `\q`.

### Приложение

Нужны [Node.js](https://nodejs.org/) 20 или новее и [pnpm](https://pnpm.io/installation). База должна быть запущена (см. выше).

1. Установите зависимости (один раз и после обновления проекта):

   ```
   pnpm install
   ```

2. Создайте таблицы в базе (один раз и после изменения схемы):

   ```
   pnpm db:migrate
   ```

3. Если нужны тестовые данные — заполните пустую базу 1000 контактами с заметками:

   ```
   pnpm db:seed
   ```

   У примерно пятой части тестовых контактов задана частота общения, поэтому блок «Пора связаться» на главной виден сразу.

   Команда работает только с пустой базой: если там уже есть контакты, она ничего не сделает и ничего не удалит.

4. Запустите приложение одним из способов:

   - **Для работы** — быстрая версия, после изменений кода её нужно пересобрать:

     ```
     pnpm build
     pnpm start
     ```

   - **Для разработки** — сама подхватывает изменения в коде:

     ```
     pnpm dev
     ```

5. Откройте http://localhost:3000

Остановить приложение — `Ctrl+C` в окне терминала, где оно запущено.

### Полезные команды

| Что сделать | Команда |
|---|---|
| Остановить базу | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Посмотреть логи базы | `docker compose logs postgres` |
| Посмотреть таблицы в браузере | `pnpm db:studio` |
| Проверить код на ошибки | `pnpm typecheck` и `pnpm lint` |

Данные хранятся в томе Docker `personal-crm_postgres-data` и не пропадают при остановке и перезапуске контейнера. Команда `docker compose down -v` удаляет этот том вместе со **всеми данными** — запускайте её, только если точно хотите начать с чистой базы.

## Требования к фичам (OpenSpec)

Фичи описываем в [OpenSpec](https://openspec.dev/docs): требования — `openspec/specs/`, текущие изменения — `openspec/changes/`. Настройки для агента (язык, контекст проекта, правила) — `openspec/config.yaml`.

Установить OpenSpec на новый компьютер (Windows, PowerShell), один раз:

```
irm https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.ps1 | iex
```

После установки перезапустите терминал и Claude Code. Проверить: `openspec --version` показывает номер версии.

Начать фичу — в Claude Code команда `/opsx:propose` с описанием фичи. Остальные команды: `/opsx:explore`, `/opsx:apply`, `/opsx:archive`.

## Как выкатить на сервер

Приложение на сервере: https://app.stayintouch.site

### Выкатить новую версию

Отправьте изменения в ветку `main`:

```
git push
```

Дальше всё произойдёт само, обычно за 3–5 минут. Следить за выкаткой: на GitHub вкладка **Actions** → **Deploy**. Зелёная галочка — новая версия на сервере.

Проверить руками: откройте https://app.stayintouch.site/health — там должно быть `"status":"ok"`, а в `version` — номер (SHA) последнего коммита. Его видно на GitHub рядом с коммитом или командой `git log -1 --format=%H`.

### Что происходит при выкатке

1. GitHub собирает образ приложения и кладёт его в GHCR (хранилище образов GitHub) с тегом — SHA коммита.
2. GitHub заходит на сервер под пользователем `deploy`, копирует туда папку `deploy/` и запускает `deploy/deploy.sh`:
   - скачивает новый образ;
   - применяет миграции базы отдельным разовым контейнером из того же образа. Если миграции упали — новая версия не запускается, продолжает работать прежняя;
   - запускает новую версию и ждёт, пока она ответит на `/health`;
   - оставляет на сервере только текущий и предыдущий образы, остальные удаляет.
3. GitHub проверяет снаружи https://app.stayintouch.site/health: ответ 200 и SHA нового коммита.

### Если выкатка упала

На вкладке **Actions** будет красный крестик, GitHub пришлёт письмо. Сама выкатка ничего не откатывает:

- упали миграции или новая версия не запустилась — откройте упавший шаг и посмотрите ошибку;
- упала последняя проверка (Smoke test) — новая версия уже запущена, но отвечает не так, как надо.

Вернуть предыдущую версию (спросит пароль sudo):

```
ssh -t crm "sudo -u deploy bash /srv/personal-crm/deploy/rollback.sh"
```

Откат возвращает только приложение: изменения базы, сделанные миграциями новой версии, остаются.

### Тестовые данные на сервере

GitHub → **Actions** → **Seed test data** → **Run workflow**. Добавляет 1000 тестовых контактов, но только в пустую базу: если в ней уже есть контакты, ничего не делает.

### Что где на сервере

| Что | Где |
|---|---|
| Папка приложения | `/srv/personal-crm`, владелец — пользователь `deploy` |
| Пароль базы | `/srv/personal-crm/.env`, права 600; какие строки там нужны — `deploy/.env.example` |
| Скрипты выкатки | `/srv/personal-crm/deploy` — копия папки `deploy/` из последней выкатки |
| Настройка nginx для приложения | `/etc/nginx/snippets/personal-crm-app.conf` |
| Данные базы | том Docker `prod_postgres-data` |

Пароль в `.env` база запоминает при первом запуске: если потом поменять его в `.env`, приложение перестанет подключаться к базе.

Посмотреть на сервере (спросят пароль sudo):

| Что сделать | Команда |
|---|---|
| Что запущено | `ssh -t crm "sudo docker ps"` |
| Логи приложения | `ssh -t crm "sudo docker logs --tail 100 prod-app-1"` |

Первичная настройка сервера под выкатку — `deploy/bootstrap.sh`. Она уже сделана, повторять не нужно.

### Настройки выкатки в GitHub

Settings → Secrets and variables → Actions:

- секрет `DEPLOY_SSH_KEY` — приватный ключ, с которым GitHub заходит на сервер;
- переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` (отпечаток сервера), `APP_URL`.
