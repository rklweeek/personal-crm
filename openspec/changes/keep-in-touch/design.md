# Design

## Context

- Данные: таблицы `contacts` и `notes` (`src/db/schema.ts`). У заметки есть только `created_at`. Сейчас заметки нельзя править и удалять по одной: удаляются они только вместе с контактом (каскадом). Эта фича добавляет одно исключение - «Отменить» удаляет только что добавленную заметку «Связались» (решение 7). Все даты - `timestamp with time zone`, то есть хранятся как точный момент времени.
- Главная (`src/app/page.tsx`) - серверный компонент `ContactList` внутри `Suspense`, читает `?q=` и параллельно грузит список и общее число. Включены `cacheComponents` (`next.config.ts`).
- Карточка (`src/app/contacts/[id]/page.tsx`) - данные контакта в `dl`, форма заметки через `useActionState` и действие `addNote`. После заметки сейчас вызывается только `refresh()`, без `revalidatePath`.
- Действия создания, правки и удаления контакта вызывают `revalidatePath("/", "layout")`. По документации Next 16 это ещё и заставляет заново загрузить ранее открытые страницы при следующем переходе на них.
- Время заметок показывает `formatDateTime` в `src/lib/format.ts` через `Intl.DateTimeFormat` без явного часового пояса, то есть в часовом поясе процесса Node. В контейнере на проде это UTC, на 3 часа меньше московского. Других мест, где приложение показывает даты, нет.
- UI-компоненты shadcn (стиль `base-nova`) построены на уже установленной `@base-ui/react` 1.9. В ней есть `Slider` с событием `onValueCommitted`: оно срабатывает, когда ползунок отпустили, и при каждом сдвиге с клавиатуры. `shadcn` уже есть в devDependencies.
- Автотестов и тестовой библиотеки в проекте нет. Проверяем сценарии из спеки руками, плюс `pnpm typecheck` и `pnpm lint`.

## Goals / Non-Goals

**Goals:**

- Одна новая колонка, миграция только добавляет. Старый образ продолжает работать с новой схемой.
- Часовой пояс приложения задан в одном месте кода и одинаков локально и на сервере.
- Расчёт срока - одна чистая функция без обращения к базе, по календарным датам Москвы.
- Ползунок и кнопка «Связались» отзываются мгновенно и не требуют формы.
- Отменённое нажатие «Связались» не оставляет следов: ни заметки, ни сдвига срока.

**Non-Goals:**

- Хранить историю общения отдельно от заметок.
- Пагинация блока: раскрытый блок показывает всех сразу.

## Decisions

### 1. Хранение частоты: enum в Postgres, колонка может быть пустой

`contacts.contact_frequency` типа `contact_frequency` (`pgEnum`: `week`, `month`, `quarter`, `year`), `NULL` = «не задано». Миграцию генерирует `pnpm db:generate` (`drizzle/0001_*.sql`): `CREATE TYPE` + `ALTER TABLE ... ADD COLUMN` без значения по умолчанию.

- Почему enum, а не `text`: база сама не пропустит неизвестное значение, а Drizzle выводит из enum TypeScript-тип.
- Почему `NULL`, а не значение `none`: «не задано» - это отсутствие значения, и фильтр «у кого задана частота» получается простым `IS NOT NULL`.
- Отдельную таблицу не делаем: у контакта одна частота.

### 2. Дата последнего общения считается при чтении, не хранится

Запрос в `src/lib/contacts.ts` (`listDueContacts`): контакты с `contact_frequency IS NOT NULL`, `LEFT JOIN notes`, `GROUP BY contacts.id`, `coalesce(max(notes.created_at), contacts.created_at)` как дата последнего общения. Индекс `notes_contact_id_idx` уже есть.

- Альтернатива - колонка `last_contacted_at`, которую обновляет `addNote`. Отказ: это дублирование, которое может разойтись с заметками. Обычные объёмы личной CRM (сотни контактов, частота задана у малой части) запрос с группировкой тянет без проблем.

### 3. Московское время - константа в коде, а не настройка сервера

В `src/lib/format.ts`: `APP_TIME_ZONE = "Europe/Moscow"`. `formatDateTime` получает `timeZone: APP_TIME_ZONE`. Там же помощник `toAppDate(date)`: календарная дата (год, месяц, день) по Москве через `Intl.DateTimeFormat("en-CA", { timeZone: APP_TIME_ZONE, ... }).formatToParts`. Им пользуется расчёт срока (решение 4) и для дат последнего общения, и для «сегодня».

- Почему не переменная окружения `TZ` в `Dockerfile` или `deploy/compose.yaml`: она чинит только сервер, а `pnpm dev` локально по-прежнему брал бы пояс компьютера. Константа в коде даёт одинаковый результат везде и видна в одном месте.
- Почему не часовой пояс сессии Postgres: даты показывает Node, и расчёт должен идти там же, где отображение.
- Хранение не меняется: `timestamptz` - точный момент, меняется только то, как он превращается в дату и время на экране.
- В Москве нет перехода на летнее время с 2014 года, но `Intl` с поясом `Europe/Moscow` и так учитывает правила сам.

### 4. Срок и просрочка считаются в TypeScript по календарным датам Москвы

Новый модуль `src/lib/keep-in-touch.ts` без `server-only`: список частот, подписи («Неделя» / «раз в неделю»), функция расчёта. Для каждой строки она берёт московскую календарную дату последнего общения (`toAppDate`), прибавляет период, сравнивает с переданной московской датой «сегодня» и возвращает срок и число дней просрочки. Месяцы прибавляются с прижатием к последнему дню месяца (31 января + месяц = 28/29 февраля). Дни считаются как разница календарных дат (через `Date.UTC(год, месяц, день)`), а не 24-часовых интервалов. Фильтр «срок ≤ сегодня» и сортировка (срок по возрастанию, при равенстве - имя через `localeCompare("ru")`) - там же.

- Почему не в SQL: у Postgres свой часовой пояс сессии, а даты заметок показывает Node. Расчёт тем же помощником `toAppDate`, что и отображение, исключает расхождение «заметка 1 октября, а срок посчитан от 30 сентября».
- Сегодняшняя дата передаётся в функцию параметром: так её легко проверить на граничных датах.

### 5. Ползунок - shadcn Slider на Base UI, сохранение по `onValueCommitted`

Компонент `src/components/ui/slider.tsx` добавляется командой `pnpm shadcn add slider` (CLI `shadcn` уже в devDependencies; стиль `base-nova`, обёртка над `@base-ui/react/slider`). Если команда меняет `package.json` - останавливаемся и спрашиваем владельца: это значило бы новую библиотеку.

Клиентский компонент `src/components/contact-frequency-slider.tsx`: подпись «Как часто общаться», ползунок `min=0 max=4 step=1` (0 - «Не задано», 1-4 - неделя, месяц, квартал, год), под дорожкой пять подписей, выбранная выделена жирным и цветом текста. Значение под пальцем меняется через `onValueChange`, а сохраняется только в `onValueCommitted`: при отпускании и при каждом нажатии стрелки. Для экранного диктора - `aria-label="Как часто общаться"` и `getAriaValueText`, который отдаёт подпись положения («Месяц»), а не число.

- Сохранение: `useOptimistic` сразу держит новое положение и вызывает действие `setContactFrequency(contactId, frequency)` в `src/app/actions.ts`. Действие проверяет значение через zod (`z.enum([...]).nullable()`), обновляет строку и вызывает `revalidatePath("/", "layout")`, чтобы главная показала свежий блок. Ошибку оно возвращает текстом.
- Нет такой строки (контакт удалили) - «Контакт не найден — возможно, его удалили», как в `updateContact` и `addNote`. Оптимистичное положение само возвращается к сохранённому, сообщение - под ползунком.
- На телефоне подпись «Не задано» переносится на две строки, чтобы не наезжать на «Неделя». Цвета и отступы - только через дизайн-токены.
- Место в карточке: новая строка в `dl` первой карточки на всю ширину (`sm:col-span-2`) под телефоном и почтой, подпись в стиле остальных полей (`Detail`).
- Почему сохранение не на каждый шаг перетаскивания: иначе протаскивание от «Не задано» до «Год» отправило бы четыре записи подряд.
- `ContactForm`, `contactSchema` и `updateContact` не меняются: `.set(result.data)` пишет только поля формы, поэтому частота при правке сохраняется сама.

### 6. Блок на главной - между поиском и списком, сворачивается до 10 строк

`ContactList` при пустом `q` дополнительно грузит `listDueContacts()` в том же `Promise.all`. Если результат не пуст, рендерит клиентский компонент блока `src/components/due-contacts.tsx`: заголовок «Пора связаться» с числом всех (как «Заметки N» в карточке), список ссылок в стиле общего списка (инициалы, имя, ниже приглушённо «раз в месяц · просрочено на 5 дней»). Порядок на странице: заголовок «Контакты» → поиск → блок → «N контактов» → список.

- Свёртывание: `useState(false)`; свёрнутый блок показывает первые 10 строк. Если строк больше 10, под списком кнопка «Показать ещё N» со стрелкой вниз (`ChevronDown` из lucide), раскрытый - «Свернуть» со стрелкой вверх. У кнопки `aria-expanded` и `aria-controls` на список. Состояние не сохраняется: после обновления страницы блок снова свёрнут.
- Сервер отдаёт всех, у кого наступил срок: строки маленькие, а число у заголовка и так нужно полное.
- Почему блок под поиском, а не над ним: блок скрывается, как только в поиске появляется запрос. Если бы он стоял над полем поиска, поле подпрыгивало бы вверх прямо во время набора. Под поиском поле остаётся на месте, а блок по-прежнему над списком контактов.

### 7. Кнопка «Связались» пишет заметку сразу, «Отменить» её удаляет

Два серверных действия в `src/app/actions.ts`, текст заметки - константа `CONTACTED_NOTE_BODY = "Связались"` в `src/lib/keep-in-touch.ts`:

- `markContacted(contactId)`: проверяет, что контакт есть (иначе «Контакт не найден — возможно, его удалили»), добавляет заметку с этим текстом и возвращает её `id`; затем `revalidatePath("/", "layout")`.
- `undoMarkContacted(noteId)`: удаляет заметку, только если у неё текст «Связались» и она добавлена не больше 2 минут назад (`created_at > now() - interval '2 minutes'`); затем `revalidatePath("/", "layout")`. Запас сверх 10 секунд - на медленную сеть. Так «Отменить» не может удалить никакую другую заметку.
- Почему заметка пишется сразу, а не через 10 секунд, если не отменили: закрой вкладку в эти 10 секунд - и отметка бы потерялась. Лучше лишняя запись, которую можно отменить, чем пропавшая.

Клиент - в том же `src/components/due-contacts.tsx`:

- Строка - `li` с двумя соседями: ссылка `Link` на карточку (инициалы, имя, частота, просрочка) и кнопка `Button variant="outline"` «Связались». Кнопка не внутри ссылки, поэтому не открывает карточку. На телефоне частота и просрочка - двумя строками, кнопка без значка; на широком экране - одной строкой, у кнопки значок `Check` из lucide.
- Нажатие: строка сразу превращается в «Заметка добавлена» + «Отменить» (состояние `pending` по `contactId` с её местом в списке), затем вызывается `markContacted`. После ответа сервер присылает блок уже без контакта, а клиент держит строку «Заметка добавлена» на её прежнем месте, чтобы список не прыгал. Через 10 секунд таймер убирает строку, и нижние контакты поднимаются. Ушёл с главной или обновил её - состояние пропадает вместе с таймером, заметка остаётся.
- «Отменить»: дожидается ответа `markContacted`, если он ещё не пришёл, вызывает `undoMarkContacted(noteId)` и убирает `pending`; сервер присылает блок с контактом на прежнем месте, потому что порядок задаёт расчёт срока.
- Двойное нажатие: пока действие идёт, кнопка неактивна; после первого нажатия её всё равно сменяет «Отменить».
- Ошибка (контакт удалили): `pending` убирается, над списком блока - сообщение через существующий `StatusMessage`, а свежий блок приходит уже без контакта.
- Доступность: у кнопок `aria-label="Связались: <имя>"` и «Отменить: <имя>» (видимый текст стоит первым); «Заметка добавлена» - в `role="status"`, чтобы экранный диктор её прочитал; после нажатия фокус переходит на «Отменить», а когда строка исчезает с фокусом на ней - на заголовок блока (`tabIndex={-1}`).
- Число у заголовка - из данных сервера, то есть без контакта, которого отметили; «Показать ещё N» считает строки, которые сейчас в списке, вместе со строкой «Заметка добавлена».

### 8. Новая заметка обновляет главную

В `addNote` к `refresh()` добавляется `revalidatePath("/", "layout")`, как у других действий. Без этого после заметки и кнопки «назад» в браузере главная может показать блок из кэша, со старым контактом.

### 9. Тестовые данные

`scripts/seed.ts` задаёт случайную частоту примерно 20% контактов. Даты добавления и заметок там уже разбросаны на два года, так что после `pnpm db:seed` в блоке сразу больше 10 контактов (видна кнопка «Показать ещё»), а у части контактов срок ещё не наступил. Скрипт по-прежнему работает только на пустой базе.

## Risks / Trade-offs

- [После выкатки время всех старых заметок на сервере станет на 3 часа больше, чем было на экране] → Это и есть исправление: теперь оно московское. Данные в базе не меняются; откат образа вернёт прежний показ.
- [Отменить можно только 10 секунд и только не уходя с главной: ошибку, замеченную позже, не исправить - заметка «Связались» останется] → Так решил владелец. Если станет мешать, удаление заметок в карточке - отдельная фича.
- [«Отменить» - первое действие, которое удаляет одну заметку] → Оно удаляет только заметку с текстом «Связались», добавленную не больше 2 минут назад, и не тронет другую, даже если передать её номер.
- [Двойное движение ползунка отправит два действия подряд] → Каждое действие записывает итоговое значение целиком, последний выбор побеждает. Других последствий нет.
- [Граничные сценарии спеки (31 января, «срок сегодня», заметка в 01:00 по Москве) не дождаться руками] → Проверяем разовым скриптом расчёта и сдвигая `created_at` заметки или контакта в Drizzle Studio (`pnpm db:studio`) локально.

## Migration Plan

1. `pnpm db:generate` создаёт `drizzle/0001_*.sql`: новый тип и колонку, без изменения существующих строк.
2. Выкатка как обычно: разовый контейнер `migrate` применяет миграцию, потом стартует новый образ, потом smoke `/health`.
3. Откат вручную, по `deploy/rollback.sh`: он заново выкатывает предыдущий образ. Миграции того образа уже применены, поэтому шаг миграций ничего не делает. Новая колонка старому коду не мешает: Drizzle выбирает только известные ему поля, а при вставке колонка остаётся пустой. Колонку и тип при откате не удаляем. Выбранные частоты сохранятся и снова появятся при следующей выкатке. Время заметок после отката снова показывается по UTC.
